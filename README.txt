虚幻项目管理器 (UEM Box)
================================
一个用 Python + PyQt6 编写的本地 Unreal Engine（虚幻引擎）项目管理器。
不用打开 Epic 启动器或 UE 编辑器，就能把散落在各块硬盘上的 .uproject 工程
集中浏览、管理与一键启动。绿色单机、数据全部本地缓存，对扫描到的工程目录只读取、绝不写入。

A local Unreal Engine project manager built with Python & PyQt6 — browse,
organize and launch all your .uproject files from one window, without ever
opening the Epic Launcher or the engine editor.


【快速开始 / Quick Start】
------------------------------------------------
1. 首次使用（或更换电脑、删了运行环境）先双击 install.bat 安装 Python 运行环境（PyQt6）。
2. 之后每次直接双击 run.bat 即可启动。
3. 启动后点工具栏「🔄 扫描」开始查找工程。

支持系统：Windows（依赖注册表里的 EpicGames 引擎路径来定位 UnrealEditor.exe）。


【主界面功能 / Features】
------------------------------------------------
· 扫描路径：可在工具栏添加/删除任意多个磁盘主路径，每个路径可单独设置"深度"
  （向下遍历几层子文件夹）。下拉框第 0 项为「全部路径」显示所有项目；
  选某条具体路径则只显示该路径下的项目，并可在「深度」框里单独调整它的遍历层数。
· 扫描：点「🔄 扫描」按配置的每路径深度查找 .uproject，发现后逐步显示。
· 版本筛选：按引擎版本（如 4.27 / 5.4）过滤。
· 搜索：按工程名实时搜索。
· 排序：按 时间 / 大小 / 名称 / 版本 排序，可切升降序；置顶项永远在最前。
        排序方式和升降序会自动记住，下次启动沿用。
· 视图切换：「▦ 卡片」= 图标网格（每个工程一个圆角框，信息分行排版，默认）；
            「☰ 列表」= 横版明细（名称 / 版本 / 上次打开 / 大小 / 路径 多列，类似资源管理器）。
· 悬停：鼠标悬停任意工程卡片或列表行，都会浮出该工程的完整磁盘路径。
· 右下角常驻显示「共 N 个工程」。
· 左下角日志：单击弹出「运行日志」窗口（本次运行的提示历史），可点 X 关闭。


【工程卡片/列表显示内容】
------------------------------------------------
· 缩略图（没有则使用默认的 DefaultThumbnail.png）
· 名称（支持自定义显示别名，不影响磁盘文件夹名）
· 目录大小（MB / GB）
· 引擎版本角标（取自 .uproject 的 EngineAssociation）
· 上次打开日期（= Saved/AutoScreenshot.png 的修改时间）
· 空项目标记：若工程目录下 Content / Plugins / Source 一个都没有，会在大小前
  以橙色「⚠ 空项目」标出（只要有其中任意一个目录即不算空）。
· 置顶标记（📌）


【右键菜单】
------------------------------------------------
· 打开项目：优先用注册表里对应版本的 UnrealEditor.exe 启动；找不到则走系统文件关联。
· 打开目录：在资源管理器打开工程所在文件夹。
· 置顶项目 / 取消置顶：置顶项永远排在最前。
· 重命名：改的是"显示名称"（存在本程序配置里），不会改动磁盘上的工程文件夹。
· 自定义封面 / 移除自定义封面：给工程指定一张图片作为缩略图，封面缓存保存在
  本程序目录下，不写入工程目录。


【工程大小统计（缓存机制）】
------------------------------------------------
为了不反复读硬盘、保护磁盘，目录大小采用本地缓存：
· 只有以下情况才会重新统计大小并写回缓存：
    1. 新发现的工程（缓存里没有）；
    2. 缓存超过 7 天未更新（SIZE_STALE_DAYS）；
    3. 工程 .uproject 文件或 Saved 目录之后被改动过（说明打开/动过工程）；
    4. 缓存里的脏记录（size ≤ 0，早年残留或统计中断产物）。
· 重新统计时按项目逐个测量，项目之间会间歇 500ms（磁盘友好），不会把硬盘打满。
· 正在统计的项目显示「⏳ 统计中」，统计完自动刷成真实大小。
· 右键「重新统计大小」可手动强制刷新某个工程。
· 注：超过 2GB 的大项目已专门修复（信号改用 64 位 qint64，不再溢出成 0 MB）。


【缩略图优先级】
------------------------------------------------
工程缩略图按以下顺序取第一张可用的：
  1. 自定义封面（右键设置的，存于本程序 covers/ 目录）
  2. 工程目录下的图片文件
  3. 工程 Saved/AutoScreenshot.png
  4. 本程序自带的 DefaultThumbnail.png（无图兜底，位于 UEMBox/DefaultThumbnail.png）
若以上都没有，则显示占位图（深灰底「UE / 暂无预览图」），不会崩溃。


【配置文件 config.json（可删除）】
------------------------------------------------
配置文件位于  UEMBox/config.json，程序首次扫描后会自动生成。
· 可随时删除：下次启动会发现文件缺失并自动写出一份默认配置（出厂恢复），
  不影响使用；你在界面上的改动会随后正常保存进去。
· 主要字段：
    "title"     窗口/标题栏显示名（写什么就显示什么，默认"虚幻项目管理器"）
    "roots"     扫描路径列表，每条 {"path": "...", "depth": N} 各自独立深度
    "sort_key" / "sort_asc"   上次使用的排序字段与升降序（自动记忆）
    "view_mode"   "card"(默认) 或 "list"
    "pinned"     置顶工程列表
    "alias"      工程显示别名  {"工程路径": "别名"}
    "covers"     自定义封面    {"工程路径": "covers/文件名"}
· 想改程序显示名：编辑 "title" 字段后重启即可。


【写入范围（只读扫描目录，安全）】
------------------------------------------------
本程序只往自己所在目录写东西：
    UEMBox/config.json   设置
    UEMBox/cache.json    项目大小等记忆缓存（自动维护）
    UEMBox/covers/       自定义封面缓存
扫描路径、工程目录一律只读取，绝不写入或修改。请放心使用。


【目录结构 / Directory Layout】
------------------------------------------------
KL虚幻盒子\              盒子根目录（只放启动方式与下面两个文件夹）
├─ run.bat        启动入口（双击它即可）
├─ install.bat    重装运行环境（Engine 缺失时跑一次）
├─ README.txt     本说明
├─ Engine\         ★ Python 虚拟环境（PyQt6 等依赖都在这里，备份时无需上传）
└─ UEMBox\         ★ 程序本体 + 数据（可直接整体备份）
    ├─ UEMBox.py   主程序（PyQt6 界面与全部逻辑）
    ├─ DefaultThumbnail.png   默认缩略图（无图兜底）
    ├─ config.json   配置（首次扫描后自动生成，可删除重建）
    ├─ cache.json    项目大小等记忆缓存（自动维护）
    ├─ covers\       自定义封面缓存
    └─ app\          代码目录（当前入口 UEMBox.py 位于 UEMBox\ 下）


【常见问题 / FAQ】
------------------------------------------------
Q：扫描路径里的大工程显示 0 MB？
A：旧版本曾有 2GB 溢出的 Bug，现已修复。若缓存里还残留负值，删除
   UEMBox/cache.json（或其中的脏条目）后重新扫描即可恢复正确大小。

Q：为什么有的工程显示「⚠ 空项目」？
A：该工程目录下没有 Content / Plugins / Source 任意一个目录，通常是占位、
   模板或还没拉取资源的工程。只要有其中任意一个就不算空。

Q：config.json / cache.json 能删吗？
A：都能。config.json 删了自动重建默认；cache.json 删了只是下次重新统计大小，
   不丢工程数据。

Q：能跨平台（macOS / Linux）用吗？
A：当前启动逻辑依赖 Windows 注册表和 .exe 关联，主要面向 Windows。
   代码本身对路径做了处理，理论上稍作适配即可迁移，欢迎 PR。
